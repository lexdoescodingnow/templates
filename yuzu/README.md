# Yuzu · Winter fruit, warm hearts

Fifteen JCink templates for **Cole & Julian**: five threads, five electronic comms and five miniature buds. Bathhouse tiles, citrus wrapping, orchard crates and folded paper give the collection its details. Member colours carry the frames, headings and emphasis over neutral writing surfaces.

[Preview and editor](yuzu-collection-preview.html)

Open a named `.txt` file and choose **Copy raw file** on GitHub. Paste the complete block, including `[dohtml]`, the stylesheet link and `[/dohtml]`, into your post. Each snippet is already connected to its shared stylesheet. No injector script is needed.

Download the preview HTML and open it in a browser to edit and compare the designs. GitHub displays HTML as source. The preview contains the styles and editor; the example GIFs need an internet connection.

## Editing

`[url]`, `[name]` and `[text]` are the first editable fields. `[text]` is the heading or contact status. Comms times, GIF URLs and writing follow, before the decorative element and stylesheet. The forum HTML and CSS contain no comments, hidden tips or editing notes.

Replace the lorem ipsum in `yzu-copy` with ordinary `<p>` paragraphs. In comms, each paragraph becomes a message bubble; successive opening `<p>` tags also work without closing tags. Set `data-flow` to `received`, `sent` or `mixed` to change message alignment. Device controls are decorative.

Buds start with a 36-word sample and are intended for replies of about 100 words or fewer. Writing grows naturally, with no fixed-height or scrolling text boxes.

The preview shows Cole & Julian with example headings. Default exports preserve the requested placeholders. Enter your actual name, title and link to include them in the copied code. Each design retains edits while the page is open. Use **Download .txt** to save an edited version.

The editor converts `[b]`, `[i]` and `[u]` into `<b>`, `<i>` and `<u>`. Raw `[dohtml]` snippets already use HTML emphasis, because BBCode processing inside those tags depends on the forum. `<strong>` and `<em>` work too. Bold and underline use the forward member gradient, 1 → 2 → 3; italics reverse it, 3 → 2 → 1.

## GIFs

The supplied Tumblr URLs are included exactly as provided. Six designs start without GIFs, five with one, and four with two. Counts are defaults, not limits. Add or remove GIFs and change crop positions in the editor. The preview and exported code use the same content model.

In raw code, edit or remove the `<img>` elements in `yzu-media`. Empty or absent image areas collapse, reclaiming their layout space. To add an image to a text-only design, insert this before `yzu-copy`:

```html
<div class="yzu-media">
<img src="[url]" alt="Character GIF" style="object-position:50% 35%">
</div>
```

Additional images wrap or stack in the media area. GIF URLs appear once per image in the editable HTML, never in the stylesheet.

## Member colours and modes

The collection inherits Blue Hour’s `--mgrgb1`, `--mgrgb2` and `--mgrgb3` as RGB triples. Missing secondary variables fall back to an available member colour. Preview sample colours apply only when inherited colours are absent. Neutral surfaces change with `html[color-mode="light"]` and `html[color-mode="dark"]`; explicit forum mode overrides system preference.

Frames, tile rules, folded corners, device bezels, image borders and headings use member colours. Small fruit and seed details carry the muted yuzu accent. All template selectors are scoped to `.bh-yuzu`; inner classes begin with `yzu-`. Typography uses local Georgia, Trebuchet MS, Arial and Courier New fallbacks. New motifs are CSS and embedded SVG masks, with no font or icon service dependency.

The stylesheet uses modern CSS grid, container queries, `:has()`, text clipping and `color-mix()`. No JavaScript is required inside forum snippets.

## Preview and copying

Choose a design or **View all 15**. The editor supports names, links, title/status, writing, GIF count and cropping, comms time and message direction. Light/dark/system, three member-colour pickers, palette presets and width controls affect the preview only. Copied posts inherit forum colours and mode.

**Copy JCink code** copies the complete post block. If clipboard access is unavailable, the code is opened and selected for manual copying. **Download .txt** exports the currently edited design.

## Files and verification

[yuzu-winter-v1.css](yuzu-winter-v1.css) is the shared stylesheet. Every snippet loads the immutable GitHub revision recorded in [stylesheet-revision.txt](stylesheet-revision.txt), served through jsDelivr.

Run `node yuzu/build.cjs` from the repository root to regenerate the snippets and standalone preview. `designs.json` holds the catalogue, and `yuzu-model.js` supplies the default content and markup. The editor interface follows the existing collections; the template layouts and motif drawings are new for Yuzu.

Run `NODE_PATH=/path/to/node_modules node yuzu/validate.cjs` with `jsdom` and `css-tree` available. [VALIDATION.md](VALIDATION.md) records the completed checks and the limits of this session.
