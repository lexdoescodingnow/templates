- Forum masterposts use centered collection headings in `[align=center][H1]COLLECTION[/H1][/align]` format. Show each design’s numbered name directly above its rendered example and copyable code, without a design description or introductory instructions. Keep the corresponding browser previews equally concise; preserve the template HTML itself.
- Keep forum snippets short: host shared CSS in this repository and include one stylesheet link inside each `[dohtml]` block. Put editable names, URLs, GIFs, timestamps and text before decorative markup and stylesheet links where possible.
- Use plain `<p>` elements for separate comms messages. Support successive opening `<p>` tags without requiring closing tags in the message container. Use ordinary paragraph markup for writing; avoid requiring a repeated class or div for every message.
- Use the member group's inherited `--mgrgb1`, `--mgrgb2` and `--mgrgb3` RGB variables. Let these colours affect the actual template design, including headers, borders, frames and appropriate surfaces. Keep the content readable on neutral light/dark surfaces. A subject's signature colour must not overwhelm the group palette.
- Bold (`b`, `strong`) and underline (`u`) use the forward gradient: group 1, group 2, group 3. Italics (`i`, `em`) use the reverse gradient: group 3, group 2, group 1.
- Support Blue Hour's `html[color-mode="light"]` and `html[color-mode="dark"]` conventions. An explicit forum mode takes precedence over a system preference fallback.
- Make comms resemble phone messages or another electronic messaging device by default, unless the user requests a different presentation. Preserve simple, editable message text and a character GIF slot.
- Keep related templates recognisably part of their themed set through typography and small motifs. Use the theme as an accent alongside member colours.
- Keep URLs editable and use readable sample titles and status values instead of visible historical `[text]` fields. Forum masterposts show full lorem ipsum in the examples but use `[TEXT GOES HERE]` or `[MESSAGE GOES HERE]` in the copyable writing areas. Keep paragraph/message structure and existing media; remove optional empty metadata. For collections listed in `ship-names.json`, prefill the editable name fields with those ship members in snippets, previews and editor defaults. Use descriptive name fields for unassigned or generic collections. Mocha & Latte uses Elias, Taeyang & Yujun together; Mocha is Elias & Taeyang and Latte is Taeyang & Yujun. GIF URLs supplied by the user are examples, never a fixed count requirement. Choose zero, one, two or more images according to each design; preserve convincing paired-image layouts, use single contact portraits where appropriate, and include image-free writing-led choices. Removing images must reclaim their space, and previews, editor defaults and posting snippets must agree apart from the intentional difference between sample writing and editing markers. Do not put comments, hidden tips, instruction blocks or editing notes inside template HTML or CSS. Documentation belongs outside the template.
