# Oats · Chen & Song

Fifteen JCink designs: five threads, five device-style comms and five miniature buds. Oats appears through millstone grooves, pressed-grain forms, folded cartons, woven borders and little flake details. Member colours carry the frames, headings and text emphasis over neutral light and dark surfaces.

[Download the preview and editor](https://github.com/lexdoescodingnow/templates/raw/refs/heads/main/oats/millhouse/oats-collection-preview.html)

Download the HTML and open it in your browser to browse all fifteen designs, change the preview palette and mode, edit the fields and copy your code. GitHub displays HTML as source rather than rendering it. The preview includes its stylesheet and editor; the placeholder GIFs require an internet connection.

For direct posting, open a named `.txt` below, choose **Copy raw file** on GitHub, and paste the full block into JCink. The `[dohtml]` tags and the hosted stylesheet link are already included.

## Editing

The editable HTML is at the top of every snippet: `[url]`, `[name]`, `[text]`, the comms time where present, GIF URLs and the lorem ipsum reply. `[text]` is the thread title or contact status. The main writing is inside `oat-copy`. Decorative markup and the stylesheet link come after your content. Posting snippets and shared CSS contain no comments, hidden tips or editing instructions.

The preview displays Chen & Song and a sample title when those fields still contain placeholders. Copied code keeps the actual field values; fill in the name and title before exporting if you want those values in the post. Edits are retained per design while the preview is open. **Download .txt** saves your edited snippet.

In the preview editor, `[b]`, `[i]` and `[u]` are converted to the corresponding HTML. In raw `[dohtml]` snippets, use `<b>`, `<i>` and `<u>`; BBCode parsing inside `[dohtml]` depends on the board. `<strong>` and `<em>` also work. Bold and underline use the forward member-colour gradient, 1 → 2 → 3. Italics use the reverse gradient, 3 → 2 → 1.

Comms messages use ordinary `<p>` elements. Successive opening `<p>` tags work without individual closing tags. `data-flow="received"`, `"sent"` and `"alternate"` set the direction for the conversation. Each default message is received. The device hardware is decorative, and the writing grows with its content.

Buds start with 36 words and are designed for replies of 100 words or fewer. The editor displays a word count.

## GIFs, colours and modes

Six designs start without images, six with one and three with two. These are design defaults. Every design accepts GIFs through the editor, which can add or remove images and adjust their vertical crop. Removing all images removes the media block and reclaims the space. For manual editing, the optional `oat-media` block belongs before `oat-copy`.

The supplied Tumblr GIF URLs are used for placeholders. The repeated first URL from the request has been normalized to one URL. There are no external decorative-image or font dependencies. Georgia, Trebuchet MS, Arial and Courier New provide the type system.

The forum supplies the RGB triples `--mgrgb1`, `--mgrgb2` and `--mgrgb3`. Available member colours also supply missing secondary colours. Preview colour controls are never inserted into posting code. Neutral ink is mixed into accent text to help preserve contrast.

Blue Hour's explicit `html[color-mode="light"]` and `html[color-mode="dark"]` modes take precedence over the operating-system fallback. CSS is scoped to `.bh-oats-millhouse` and `oat-` child classes. Designs have no IDs or scripts in forum posts and can appear together. Modern CSS grid, `:has()` and `color-mix()` are used.

This collection lives in `oats/millhouse` to preserve the separate Oats work already being added to the parent folder. Its styles use `.bh-oats-millhouse` so the sets can coexist.

## Source and verification

The snippets load [oats-millhouse-v1.css](oats-millhouse-v1.css) through jsDelivr at the immutable GitHub revision recorded in [stylesheet-revision.txt](stylesheet-revision.txt). The preview embeds the same CSS. No separate JavaScript injection is needed on the forum.

Run `node oats/millhouse/build.cjs` from the repository root to rebuild all fifteen snippets and the preview. `designs.json` holds the names and starting layouts, while `oats-model.js` generates posting markup. `oats-editor.js` and `oats-preview.css` are used only by the preview.

[VALIDATION.md](VALIDATION.md) records the checks and their limits. Visual browser validation and a live JCink posting test have not been completed.
